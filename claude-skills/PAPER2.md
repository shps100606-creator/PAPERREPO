# 上層文件的精簡之路：從膨脹到整併的設計決策

> 作者：shps100606-creator × Claude Code
> 撰寫時間：2026-05-21
> 版本：1.0
> 背景版本：SKILL_2.0

---

## 摘要

本文記錄 SKILL_2.0 中針對 Claude Code 上層文件體系的重整過程。

PCM 3.0 解決了工作流程的問題，但沒有解決另一個在實際操作中浮現的問題：**每次工作的起點與終點——上層文件——是否足夠精簡、可維護？**

SKILL_2.0 沒有改動 PCM 的三段式工作流，改動的是工作前必讀、工作後必更新的那幾份文件。過程中經歷了一次拆分嘗試、一次診斷失敗、兩次整併，最終形成一套有明確依據的放置原則。

---

## 一、為什麼 CLAUDE.md 需要縮小

CLAUDE.md 是每次 session 啟動時**強制全文載入**的文件。它的 token 成本固定，與內容長短直接相關。

隨著專案演進，CLAUDE.md 容易積累三類內容：

| 類型 | 特徵 | 是否每次都需要 |
|------|------|______________|
| 核心守則 | 版本號、啟動順序、禁令 | **是** |
| 即時查閱型 | 架構圖、欄位對應、模組表 | 否（開發時才需要）|
| 操作流程型 | 部署步驟、Skill 撰寫規範 | 否（特定情境才觸發）|

**縮小的原則是搬家，不是刪除。** 核心守則留下，其餘依使用時機移出。

---

## 二、`.claude/rules/` 的問題

Claude Code 的 `.claude/rules/` 在沒有 file-scoping 設定的情況下，載入行為與 CLAUDE.md **完全相同**：session 啟動時全部強制載入。

| 文件類型 | 載入時機 | 實際效果 |
|---------|---------|----------|
| `CLAUDE.md` | 啟動必載 | 基準成本 |
| `.claude/rules/*.md`（無 file-scope）| 啟動全部必載 | **token 零節省，只增加檔案數** |
| `.claude/skills/*.md` | 按需載入 | 實際節省 |

把內容從 CLAUDE.md 移到 rules/ 的結果：一個大檔拆成多個小檔，每次 session 仍然全部讀取，成本不變。

## 三、文件放置決策樹

```
這份知識換一個完全不同的專案還有用嗎？
  ├── 有用 → 放 claude-skills/steps/X/skills/
  └── 沒用（專案專屬）→
        它和其他文件在使用時機上幾乎總是同時出現嗎？
          ├── 是 → 合併成一份文件
          └── 否 → 獨立建立 .claude/skills/{name}.md

這份知識每次 session 啟動都一定需要嗎？
  ├── 是 → 放 CLAUDE.md（保持精簡）
  └── 否 → 移出 CLAUDE.md，進 Skill
```

---

## 四、最後形成的架構

```
每次 session 必載：
  CLAUDE.md
    → 版本號、啟動順序、核心禁令、Skill 索引

按需載入（project-level）：
  .claude/skills/line-crm-architecture.md
    → 架構說明 + 模組表 + 欄位對應 + 程式碼索引（合一）

按需載入（cross-project）：
  claude-skills/steps/X/skills/
    → 通用工程模式、PCM 流程 Skill
```

### 上層文件責任清單

| 文件 | 位置 | 更新頻率 | 觸發條件 |
|------|------|---------|----------|
| `CLAUDE.md` | repo 根目錄 | **每版必更新** | 版本號、接手說明、核心禁令異動 |
| `ROADMAP.md` | `_docs/strategy/` | **每版必更新** | 功能地圖狀態、版本歷程 |
| `README.md` | repo 根目錄 | 條件更新 | 架構重大變動、對外說明需更新 |
| `.claude/skills/*.md` | repo `.claude/skills/` | 條件更新 | 模組增刪、欄位結構或架構調整 |

## 五、常見誤判對照

| 誤判 | 正確做法 |
|------|----------|
| 「內容太多，拆成多個 rules/ 檔案」 | rules/ 無 file-scope 時 token 不節省，改用 Skill |
| 「這是架構知識，放 claude-skills 通用 Skill」 | 專案專屬知識放 project repo `.claude/skills/` |
| 「這兩份文件功能不同，應該分開放」 | 使用時機相同 → 合併 |
| 「先建立，之後再整理」 | 文件一旦有引用就難以移動，決策在建立時做 |
| 「精簡就是刪掉」 | 精簡是搬家：從必載移到按需，內容還在 |
