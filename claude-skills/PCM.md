> 詳細執行指引見 `steps/` 資料夾。本文件是入口索引。

---

## 三板塊

| 板塊 | 內容 | 完成條件 | 詳細指引 |
|------|------|---------|----------|
| **前** | 環境確認 → 專案接手 → 需求訪問 → 計畫書 | 計畫書已存檔，路線確認 | `steps/前/guide.md` |
| **中** | 執行迴圈（push → deploy → verify）× N | Milestone 全勾，審查報告定稿 | `steps/中/guide.md` |
| **後** | 強制收尾清單 | 路線 A：4 項全勾；路線 B：3 項全勾 | `steps/後/guide.md` |

> 各板塊 guide.md 已內嵌對應 Skill 索引，依情況選讀 `steps/{前|中|後}/skills/` 下的個別 skill 檔案。

## 版本文件清單（路線 A）

每個版本應在對應分支的 `_docs/versions/{VERSION}/` 產生以下文件：

| 文件 | 產生板塊 | 說明 |
|------|---------|------|
| `需求訪問.md` | 前 1C | 使用者本輪意圖、已確認需求、不做事項 |
| `版本更新計畫書.md` | 前 1D | Push 清單、Milestone Checklist、相依確認 |
| `審查報告.md` | 中（執行中持續更新） | 每個 Push 的完成項目與驗證結果，Milestone 全勾後定稿 |
| `覆盤.md` | 後 A1 | 做得好/不好的地方、下次改進行動 |
| `封存紀錄.md` | 後 A4 | 版本快照、文件清單、GAS 版本與 Deployment ID |

版本分支 merge 到 main 後，再更新：
- `_docs/strategy/ROADMAP.md`
- project repo 根目錄 `CLAUDE.md`

## 路線判斷（1D 計畫書完成後）

```
路線 A（有實作）→ 前 → 中 → 後A
  版本更新計畫書 / 有整理動作的文件架構 / Skill 庫維護 / 模組規劃有實作

路線 B（純規劃）→ 前 → 後B（跳過中）
  戰略規劃書 / 模組規劃純方向 / 文件架構純規劃
```

## 禁止行為

| 禁止 | 正確做法 |
|------|----------|
| Milestone 全勾但審查報告未定稿就進後板塊 | 審查報告定稿才能離開中板塊 |
| 未完成需求訪問書就開始執行 | 前 1C 必做 |
| 未產出計畫書就修改程式碼 | 前 1D 必做 |
| 未在 1D 判斷路線就進中板塊 | 路線必須在 1D 明確確認 |
| Skill 萃取判斷結果不記錄 | 萃取或不萃取都要明確記錄原因 |
| 路線 B 執行 merge / Tag | 路線 B 只需 push branch |
| merge / Tag 前未告知使用者 | 後A 第 4 項必須等使用者確認 |
| push 前未讀相依模組介面 | 每次 push 前確認所有相依函式參數格式 |
| 一次 push 多個不相關檔案 | 一次 push 對應一個可獨立驗證的單元 |
| 覆盤只寫「完成」 | 必須包含落差、踩坑、下一輪方向 |
| 版本文件推到 main（merge 前）| 版本文件全程在版本分支，merge 後才進 main |
